## 2. 结论

不改协议、不改格式、净改动 **+27/−4 行**，两处优化（写侧 UTF 微优化 + 读侧StringBuilder 复用）：读侧 B/op 单线程 **−17.1%**、并发 8 线程 **−10.5%**（字符串载荷−22%~−54%），写侧 CJK 吞吐 +3.0%；jtreg **160/160**、语义穷举等价、字节级兼容。

## 7. 已排除的候选（审"为什么只改这两处"）

| 候选 | 排除依据（证据） |
|---|---|
| FieldValues/slotValues 池化 | K=128 每对象仅 147–286 B；stack 占比 ~1.2% → 改了测不出 |
| MAX_BLOCK_SIZE / 块缓冲 | 跨 1 KiB 边界只慢 2–4% |
| `utfLen` 按 String coder 分流 | 占写侧仅 6.9%；需动 `JavaLangAccess` 公共接口 |
| 写侧批量向量化编码 | JIT 已内联至 writeString；1.88× 为结构性成本，超出低风险补丁范围 |
| Analytics 大对象 | per-byte/GC 主导、噪声 ±38%+，非算法热点 |

每个候选的测量证据见 [4-优化实验全记录.md](4-优化实验全记录.md) 与两份方案文档。
